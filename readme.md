# Авторизация и Swagger

## JWT

Аутентификация — по JWT (алгоритм HS256). Токен создаётся на `POST /api/users/auth`
и передаётся в заголовке `Authorization: Bearer <token>`.

- Шифрование подписи — секрет `JWT_TOKEN` из `.env`, время жизни `JWT_EXPIRES_IN` (по умолчанию `1h`).
- Полезная нагрузка токена — `ds.JWTClaims` (`internal/app/ds/jwt.go`): стандартные поля RFC 7519
  (`ExpiresAt`, `IssuedAt`, `Issuer`) + `user_id`. Роли в токене нет.
- Создатель услуги (автозаполнение `user_id` при создании черновика) и текущий пользователь
  для признаков `is_creator`/`is_liked` и лайков определяются из `user_id` токена.
  Singleton-константа из лабораторной №3 удалена.

Коды ошибок:

- `401` — токена нет, он недействителен или уже в чёрном списке, а также неверный логин/пароль.
- `403` — авторизованный пользователь пытается опубликовать или удалить услугу другого пользователя.
- `404` — услуги с таким id нет (просмотр, публикация, удаление).

## Blacklist в Redis

Деавторизация (`POST /api/users/logout`) не удаляет токен, а кладёт его в чёрный список Redis
на оставшийся срок жизни токена. При каждом запросе валидность токена сначала проверяется
по чёрному списку.

Сервис Redis добавлен в `db/docker-compose.yml` (`redis:6.2-alpine`, порт `6379`,
пароль `password`, volume `redis-data`). Ключи черного списка имеют префикс
`patients_categories.jwt.` (правило префиксов с разделителем `.`), посмотреть их можно:

```
redis-cli -h localhost -p 6379 -a password
KEYS *
```

## Swagger

Генерация из комментариев (`swag init -g cmd/patients_categories/patients_categories.go`),
файлы в `docs/`. UI: `http://localhost:8080/swagger/index.html`.

Без авторизации в Swagger доступно только чтение данных (плитка, лента), регистрация
и аутентификация. Методы создателя и все изменяющие методы помечены «замком»
(`@Security BearerAuth`): чтобы открыть их в UI, нажмите `Authorize` и введите `Bearer <token>`.

# HTTP-методы

Адрес сервера: `http://localhost:8080`. Все методы начинаются с `/api`.
Ответ — JSON самого ресурса, без обёртки: код состояния передаётся HTTP-статусом,
тело при ошибке пустое.

1. `GET /api/patients_categories` — плитка: список опубликованных услуг с признаком `is_creator`, фильтрация по возрасту `?age=N`.
   Открыт без авторизации. Успех: `200` + массив услуг. Ошибки: `400` — некорректный `age`.
2. `POST /api/patients_categories` — создать черновик услуги с файлами изображения и видео; создатель берётся из JWT.
   Требует авторизацию. Тело запроса: `multipart/form-data` с полями `name`, `image`, `video`.
   Успех: `201` + услуга. Ошибки: `400`, `401`, `409` (у пользователя уже есть черновик).
3. `GET /api/patients_categories/draft` — черновик текущего пользователя, id не указывается (не более 1 записи).
   Требует авторизацию. Успех: `200` + услуга. Ошибки: `401`.
4. `GET /api/patients_categories/feed` — лента опубликованных услуг с признаком `is_liked`: без параметров первая, `?id=X&next=true` — следующая после `X`.
   Открыт без авторизации. Успех: `200` + услуга. Ошибки: `400` — некорректный `id`.
5. `PUT /api/patients_categories/:id/publish` — публикация черновика, статус `draft` → `published`; только создатель услуги.
   Требует авторизацию. Тело запроса: JSON с полями `description`, `age`, `weight`.
   Успех: `200` + услуга. Ошибки: `400`, `401`, `403` (услуга другого пользователя), `404` — услуги нет.
6. `POST /api/patients_categories/:id/like` — лайк от текущего пользователя: `1` поставить, `0` снять.
   Требует авторизацию. Тело запроса: JSON `{"like": 1}` или `{"like": 0}`.
   Успех: `200` + `{"id": N, "likes": K}`. Ошибки: `400`, `401`.
7. `DELETE /api/patients_categories/:id` — удаление услуги текущего пользователя, статус меняется на `deleted` (soft delete).
   Требует авторизацию. Успех: `200`. Ошибки: `400`, `401`, `403` (услуга другого пользователя), `404` — услуги нет.
8. `POST /api/users/register` — регистрация пользователя; пароль сохраняется как sha1-хэш.
   Тело запроса: JSON `{"username": "admin", "password": "123456"}`.
   Успех: `201` + пользователь. Ошибки: `400` — пустые поля, `409` — логин уже занят.
9. `POST /api/users/auth` — аутентификация, при успехе возвращает JWT.
   Тело запроса: JSON `{"username": "admin", "password": "123456"}`.
   Успех: `200` + `{"access_token": "...", "expires_in": 3600000000000, "token_type": "Bearer"}`.
   Ошибки: `400`, `401` — неверный логин или пароль.
10. `POST /api/users/logout` — деавторизация: текущий токен попадает в чёрный список Redis.
    Требует авторизацию (заголовок `Authorization: Bearer <token>`).
    Успех: `200`. Ошибки: `401` — нет или неверный токен.

### Модель услуги в JSON

Поля JSON фиксированы: если значение пустое, поле всё равно присутствует.

```
id · name · description · age
weight · image_url · video_url
likes · creator_id
created_at · updated_at
```

- `creator_id` — id создателя услуги, единственное поле пользователя в модели услуги: вложенного объекта нет.
- `likes` — количество лайков; в таблице не хранится, считается при сериализации.
- `status` и `user_id` клиенту не передаются: статус услуги — системное поле, вместо `user_id` отдаётся `creator_id`.

Эта базовая модель возвращается в ответах создания, черновика и публикации. Ещё два признака
добавляются только в своих запросах и в остальных ответах отсутствуют:

- `is_creator` — только в плитке (`GET /api/patients_categories`): `1`, если услуга создана текущим пользователем, иначе `0`.
- `is_liked` — только в ленте (`GET /api/patients_categories/feed`): `1`, если текущий пользователь лайкнул эту услугу, иначе `0` (вычисляется по таблице `likes`).

Создание услуги двухступенчатое: `POST` создаёт черновик (`name`, `image_url`, `video_url`,
остальные поля пустые), `PUT .../publish` заполняет `description`, `age`, `weight`
и переводит услугу в `published`. Вернуть услугу из `published` в `draft` нельзя.

# Таблицы БД

Взаимодействие с БД через ORM (GORM). Миграции — `cmd/migrate`, модели — `internal/app/ds`.

### `patients_categories` — услуги

- `id` — `bigint`, первичный ключ, автоинкремент. В JSON: `id`
- `name` — `varchar(255)`, `not null`. В JSON: `name`
- `description` — `text`. В JSON: `description`
- `status` — `varchar(20)`, `not null`, по умолчанию `draft`, CHECK `status_in` (`draft`, `published`, `deleted`), индекс. Клиенту не передаётся
- `image_url` — `varchar(255)`, `not null`, по умолчанию `/static/image/default.jpg`, ссылка на файл в MinIO. В JSON: `image_url`
- `video_url` — `varchar(255)`, `not null`, по умолчанию `/static/image/Default.mp4`, ссылка на файл в MinIO. В JSON: `video_url`
- `age` — `bigint`. В JSON: `age`
- `weight` — `numeric(5,2)`. В JSON: `weight`
- `created_at` — `timestamptz`, по умолчанию `now()`. В JSON: `created_at`
- `updated_at` — `timestamptz`, по умолчанию `now()`, меняется при публикации и удалении. В JSON: `updated_at`
- `user_id` — `bigint`, `not null`, индекс, внешний ключ на `users(id)`. Заполняется на бэкенде из JWT. В JSON не передаётся, вместо него отдаётся `creator_id`, а `is_creator` — только в плитке

Файлы изображений и видео хранятся в MinIO в бакете `body-mass-index` с именами
`pc_<id>_img.<ext>` и `pc_<id>_video.<ext>`; в БД сохраняются только ссылки на них.

### `likes` — лайки

- `id` — `bigint`, первичный ключ, автоинкремент
- `user_id` — `bigint`, `not null`, внешний ключ на `users(id)`
- `patients_categories_id` — `bigint`, `not null`, внешний ключ на `patients_categories(id)`

Уникальный индекс `idx_likes_user_patients_categories (user_id, patients_categories_id)` —
один пользователь не может поставить два лайка одной услуге. Количество лайков не хранится,
считается `COUNT` при сериализации.

### `users` — пользователи

- `id` — `bigint`, первичный ключ, автоинкремент. В JSON: `id`
- `username` — `varchar(50)`, `not null`, `unique`. В JSON: `username`
- `password_hash` — `varchar(255)`, `not null`. Клиенту не передаётся

Пароль хранится в виде sha1-хэша (`internal/app/handler/auth.go`, `generateHashString`).
Миграция `cmd/migrate` перевела пароли, созданные в лабораторной №3, из открытого текста
в хэши (идемпотентно: значение из 40 hex-символов уже считается хэшем). Значение `user_id`
в услугах подставляется из JWT на бэкенде и с клиента не передаётся.
